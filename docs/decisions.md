# 决策记录

只记录**不可逆或改起来很贵**的选择。可以边做边改的东西不写在这里，
统一放 `docs/open-questions.md`，等实现验证后再升格。

## D1 — 隔离后端用 bubblewrap，只做 Linux

背景：36 小时交付、桌面目标、不能要求 root 守护进程、演示机未必有 KVM。
决策：非特权 user namespace，`bwrap` + `--unshare-all` + `--unshare-net` +
`--clearenv` + `--cap-drop ALL`。
后果：毫秒级启动、无需安装权限、与内核共享隔离边界；不支持 macOS / Windows。
microVM 与 Seatbelt 后端仅在路线图上，**不得描述为虚拟机级隔离**。

## D2 — 不做 TLS 中间人

背景：三个目标 agent 都支持自定义 base URL。
决策：把 base URL 重写到 loopback 端点，broker 在宿主侧做协议级反代与 header 注入。
后果：不需要 CA、不受证书固定影响。代价是沙箱内原生 `git push` 无法注入凭据，
写操作改走 MCP。这条改动会波及几乎所有模块，因此先定。

## D3 — 未引入 codebase，因此不打 `v0` tag

背景：仓库 2026-10-24 从空开始，没有可复用的现成代码库。
决策：v1 不 vendor 任何第三方代码。若后续必须引入，该导入单独成为一个 commit，
在其上打 `v0`，团队改动只能叠加在其后。
后果：仓库历史干净，未引入外部代码；未来任何 vendor 行为都必须显式处理。

## D4 — 单人作品、本地演示

背景：单人开发，演示在 Linux 本地进行；不引入托管环境（会带来网络、鉴权与成本风险）。
决策：单人开发，所有变更走 PR 自审合并；演示环境为 Linux 本地。
后果：没有第二人兜底，因此把可验证性前置到自动化脚本与验收用例。
