# 测试与验收

## 0. 原则

验收必须满足三条：**可判定**（机器给结论，不靠人看）、**可重复**（同一条命令两次结果相同）、
**不依赖秘密**（测试过程不使用任何真实凭据，也不以公网可用为前提）。

第二条和第三条决定了整体设计：**用测试替身代替真实上游与真实 agent**，否则验收就变成了
"在某个特定网络环境、某个特定账号下能跑"。

## 1. 六层测试

| 层 | 目标 | 依赖 | 运行位置 | 入口 |
| --- | --- | --- | --- | --- |
| L0 环境自检 | 前置条件是否具备 | 无 | 宿主 | `twinbox doctor` |
| L1 单元 | 策略匹配、路径判定、配置生成 | 无 | 宿主 | `go test ./...` |
| L2 集成（宿主侧） | broker 注入、审计、拒绝；MCP 网关注入与分发 | 假上游、假 MCP | 宿主 | `go test ./internal/...` |
| L3 沙箱行为 | 挂载表、环境变量、网络、可见路径 | bwrap | 沙箱 | `make sandbox-test` |
| L4 红队 | 攻击用例（凭据、外发、注入、撤销） | bwrap + 假上游 | 沙箱 | `make attack` |
| L5 端到端 | 一个 agent 完成一轮对话 | 假 agent 或真实 agent | 宿主 + 沙箱 | `make e2e` |
| L6 可公开性 | 快照中没有密钥 | 无 | 宿主 | `twinbox prove` |

L1–L2 能在 CI 跑；L3–L6 需要 bwrap，只在本地或专用 runner 上跑。
**这个分工要写死在 Makefile 里，不能靠口头约定。**

## 2. 一键与退出码

```bash
make verify     # L0 + L1 + L2 + L3 + L4 + L6，全部通过才返回 0
make verify-ci  # 仅 L1 + L2 + 密钥扫描，供 CI 使用
make attack     # 只跑 L4，用于演示与回归
make e2e        # L5，默认用假 agent
```

每条用例输出一行 `PASS/FAIL <编号> <说明>`，失败时把实际输出一并打印。
最终汇总写入 `/tmp/opencode/twinbox-verify.json`，便于无人值守时事后核查。

## 3. 测试替身

| 替身 | 代替什么 | 怎么用 |
| --- | --- | --- |
| **假上游** | 真实的 LLM / Git 服务 | `httptest` 起本地服务，broker 的上游映射指向它，断言收到的 header 与路径 |
| **假 agent** | claude / codex / opencode | 一个十几行的脚本：读环境变量、向 base URL 发一次请求、打印结果、退出 |
| **假 MCP server** | 真实的 stdio MCP | 最小实现：处理 `initialize` 与 `tools/list`，返回固定工具 |

替身的意义：**把"能不能跑"和"账号/网络/版本"解耦**。真实 agent 只在 L5 的"可选"分支里跑。

## 5. 已知不可测（诚实清单）

| 项 | 原因 | 替代做法 |
| --- | --- | --- |
| macOS / Windows 后端 | 无对应机器 | 只做接口与文档，不做验收声明 |
| 真实模型的被注入行为 | 不可复现 | 用固定脚本模拟注入文本，验证"权限不会扩大" |
| 文件事件（watch）可靠性 | 环境相关 | 不测 |
| 长时间凭据过期的实际交互 | 需要等 8 小时 | 用可配置的短 TTL 触发 |
| 内核级逃逸 | 超出威胁模型 | 不测 |

## 6. 无人值守时的风险与应对

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | 无外网或无法安装 agent | L5 跑不起来 | 默认走假 agent；真实 agent 为可选分支 |
| 2 | 真实凭据不可用（也不该用） | 无法测注入 | 全部用假上游 + 占位符 |
| 3 | CI 环境不支持非特权 userns | L3/L4 失败 | CI 只跑 L1/L2；沙箱测试标记为本地专用 |
| 4 | 端口冲突 | 测试随机失败 | 一律 unix socket 或 `:0` 动态端口 |
| 5 | 临时文件残留 | 磁盘涨、结果污染 | 每个用例 `t.TempDir()`；Makefile 退出时清理 |
| 6 | agent 版本差异导致配置格式变化 | 适配器失效 | 适配器以文件为准，不依赖 CLI 参数；doctor 报版本 |
| 7 | 审计对账出现无法解释的差 | 判据 18 失败 | broker 是唯一真源；测试断言条数而非内容 |
| 8 | 时间不足 | 功能缺失 | 按 §7 的降级顺序砍，文档同步标 roadmap |
| 9 | 测试依赖本机路径 | 换机器失败 | 用例只用 `t.TempDir()` 与传参路径 |
| 10 | bwrap 版本差异（overlay 等） | 启动参数不被识别 | doctor 检查版本；可选特性用能力探测，不硬编码 |

## 7. 降级顺序（时间不够时按此砍）

1. `prove` 的完整扫描 → 降为只扫关键目录
2. MCP 网关的多 server → 只保留一个
3. 第三个 agent 适配器 → 只保 claude + opencode
4. 授权弹窗 → 改为显式 allowlist 参数
5. **永不砍**：L0、L1、L2、L3 的核心用例、`make attack` 可运行、doctor 可读

## 8. 环境前提（doctor 必须逐项报告）

| 检查项 | 不满足时的表现 |
| --- | --- |
| `bwrap` 存在且可创建 userns | 沙箱无法启动 |
| 内核允许非特权 userns | `bwrap: Operation not permitted` |
| 可写的运行时目录 | socket 创建失败 |
| profile 目录可读 | 挂载为空，agent 报命令找不到 |
| agent 二进制存在 | 适配器无法执行（不阻塞 doctor 通过） |
| 端口/socket 无占用 | 桥接启动失败 |
